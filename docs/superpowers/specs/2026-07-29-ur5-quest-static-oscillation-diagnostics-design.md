## 1. 问题与实测现象

Quest 3 Build & Run 后，用户确认以下现象：

- 右手 Grip 松开时，Unity 虚拟 UR5 保持正常；
- 右手 Grip 按住且手柄保持不动时，肩、肘、腕全部关节持续摆动；
- 右手 Grip 按住并主动移动手柄时，机械臂反而相对平稳；
- 当前相对 6DoF 朝向难以精确设为竖直向下；
- 计划中的左手安全朝下入口没有生效。

第一项属于 Task 7 安全阻断问题。在根因得到运行日志确认前，不接受当前 Quest 参数，不把 9.3 标记为完成。

## 2. 已确认的代码问题

`Ur5ControlBootstrap.ApplyDefaultQuestTeleopProfile` 为右手完整 6DoF 将
`rotationControllerNode` 设置为 `XRNode.RightHand`。与此同时，
`Ur5CartesianVelocityTeleopController.UpdateLeftControllerSafetyPose` 仍通过
`rotationControllerNode` 和 `rotationDevice` 读取左手 X/Grip，并在节点不是
`XRNode.LeftHand` 时直接退出。

因此左手安全朝下入口与右手旋转输入错误地共享同一设备字段。该问题的修复不依赖振荡日志，可以通过独立左手安全输入设备和自动化测试确定性解决。

## 3. 振荡诊断边界

本轮首先制作诊断版本，不修改以下控制行为和参数：

- `Ur5Continuous6DofConfig` 的平移/旋转增益；
- 最终位姿滤波时间常数；
- 最大线速度和最大角速度；
- DLS 阻尼、增益、容差和关节速度；
- Articulation Drive 刚度、阻尼和领先量；
- 单模式 Grip 交互和四元数映射顺序。

这样可以保留用户复现问题时的原始条件，避免日志同时混入未经验证的参数修正。

## 4. 诊断数据流

### 4.1 自动记录生命周期

Quest Android 运行时自动开始记录；Editor 和其他平台保持默认不自动记录，避免影响日常编辑。

记录器采用可配置的定期落盘机制，并在以下时机强制保存：

- 到达固定落盘间隔；
- `OnApplicationPause(true)`；
- `OnApplicationQuit()`；
- 组件禁用或销毁。

重复保存必须幂等，不得因多个 Unity 生命周期回调重复追加表头或丢失已采样数据。日志仍写入
`Application.persistentDataPath/ur5_pose_log.csv`，便于通过 ADB 从应用外部文件目录拉取。

### 4.2 必要字段

保留现有 CSV 前缀和已经追加的连续 6DoF 列，所有新列继续追加在末尾。至少记录：

- 原始右手世界位置和四元数；
- 连续控制器相对距离、相对角度和当前增益；
- 逻辑目标位置和四元数；
- 工作空间约束后位置；
- 最终滤波位置和四元数；
- 实际两指中心位置和实际抓取坐标系四元数；
- TCP 位置误差和姿态误差；
- 静止目标累计时间、静止保持是否锁存；
- DLS 最小主元、近奇异标志、IK 失败次数和关节领先限幅状态；
- 六个关节的命令目标、Drive 目标和实测角度。

字段必须使用米、度、秒和四元数原值，禁止通过欧拉角作为诊断真值。诊断属性只读，不允许为了记录而改变 IK 或控制状态。

### 4.3 根因分类规则

复现后按以下顺序判断：

1. 原始手柄四元数静止时持续变化，逻辑目标同步变化：XR 姿态噪声进入映射；
2. 原始输入稳定，逻辑目标变化：离合基准或四元数映射问题；
3. 逻辑目标稳定，滤波目标变化：滤波状态或多次写入问题；
4. 滤波目标稳定，关节目标往返变化：IK 静止收敛或奇异性问题；
5. 关节目标稳定，实测关节持续摆动：Articulation Drive/物理参数问题；
6. 静止保持状态反复开关：静止阈值与目标噪声发生锁存抖动。

只有日志明确命中某一层后，下一轮才允许针对该层做单变量修复。

## 5. 左手安全朝下控制

### 5.1 输入所有权

新增独立的左手安全输入设备，固定从 `XRNode.LeftHand` 读取：

- 左手 Grip 是安全按键的 deadman；
- 左手 Grip + 点按 X：把物理抓取方向精确设为世界坐标 `Vector3.down`；
- 左手 Grip + 长按 X：保持现有 Ready Pose 行为；
- 右手 Grip 按住时，左手 X 不得取得 `TcpTarget` 写入权；
- 安全姿态取得写入权后，右手必须松开并重新按下 Grip 才能重新离合。

右手 `positionControllerNode` 和 `rotationControllerNode` 继续固定为 `XRNode.RightHand`，不得为了恢复左手 X 而退回左手旋转控制。

### 5.2 朝向语义

朝下命令继续使用 `Ur5TcpTargetFollower.GetToolRotationForGraspApproach`，由实际两指中心抓取坐标系计算 tool0 目标旋转，不新增场景专用欧拉角或轴交换。

完成朝下对准后，用户松开左手 X/Grip，再按右手 Grip，以当前实际 TCP 姿态建立新的相对 6DoF 基准。右手仍可在该基准上进行完整旋转微调。

## 7. Quest 复现流程

本地测试通过后先向用户汇报，未经确认不执行 Build & Run。确认后只控制 Unity 虚拟 UR5：

1. 启动应用并等待机械臂稳定；
2. 保持右手柄静止，不按 Grip 记录 5 秒基线；
3. 按住右手 Grip，继续静止 10 秒，复现全臂持续摆动；
4. 保持 Grip 并缓慢平移/旋转 10 秒；
5. 松开 Grip，记录 5 秒恢复段；
6. 松开右手 Grip，验证左手 Grip + 点按 X 的朝下控制；
7. 退出或暂停应用，使用 ADB 拉取 CSV 和 Unity 日志。

若机械臂摆动幅度明显增大，立即松开 Grip，不延长复现时间。
