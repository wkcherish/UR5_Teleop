# UR5 单模式 6DoF 离合遥操作设计

- 日期：2026-07-29
- 状态：用户已批准交互、架构、映射、安全与验证设计
- 适用工程：`/Users/imi-1/Desktop/project/ur5`
- 适用阶段：第九阶段 9.3 的控制体验修正

## 1. 背景与问题

当前 Quest 运行配置由 `Ur5ControlBootstrap.ApplyDefaultQuestTeleopProfile` 在启动时覆盖为左手摇杆旋转。标准运行路径仅启用了夹爪轴向旋转，pitch/roll 速度为零；右手柄姿态没有进入 TCP 的标准旋转指令链路。因此，用户在右手 Grip 遥操作时没有获得完整的末端旋转控制。

现有实现同时保留了三模式切换、左摇杆旋转、左手 Y 姿态旋转、姿态锁定和自动竖直吸附等多条分支。它们增加了输入所有权和运行配置互相覆盖的风险，不符合用户要求的“一个模式即可丝滑、稳定且精确”。

用户已明确批准将标准交互改为：

- 右手 Grip 按下时，以按下瞬间为基准控制完整 6DoF；
- 右手柄平移和 yaw/pitch/roll 同步映射到 TCP；
- 松开 Grip 后立即保持，不继续追赶；
- 不使用 A/B 切换 free/fine/insert；
- 不依赖左摇杆或左手姿态控制旋转；
- 小动作自动精细，大动作连续提高响应；
- Grip 控制期间不执行自动竖直吸附或姿态轴锁；
- 右手扳机继续只负责夹爪开合；
- 左手 X 可保留为 Grip 未按下时的显式安全姿态复位。

## 2. 与原 9.3 计划的关系

原 9.3 计划要求 free、fine、insert 三种运动配置。用户已明确批准把标准操控改成单一连续模式，因此本设计是对原计划运动模式部分的显式变更。

仍然保留原计划的以下安全契约：

- Grip 按下捕获手柄与实际 TCP 基准；
- Grip 松开停止更新；
- `Idle / Clutched / Paused / Fault` 状态明确；
- 输入、机器人状态或安全异常默认停止；
- 参数版本化，单位和失败行为显式；
- 重复离合不产生目标突跳；
- 工作空间、速度、角速度和单步增量限制不能被绕过。

## 3. 参考实现结论

参考项目 [elpis-lab/UR10_Teleop](https://github.com/elpis-lab/UR10_Teleop) 的核心方法是：

1. 离合恢复时同时捕获控制器位姿和实际工具位姿；
2. 后续目标始终由这组固定基准计算，而不是逐帧积分；
3. 相对旋转使用 `current * inverse(anchor)`；
4. 相对四元数左乘工具基准四元数，形成全局工具目标；
5. 位置用线性插值、旋转用 SLERP，只对最终目标执行一次平滑。

本设计复用上述数据流，但不直接复制其固定刷新率参数。Quest 可能运行在 72/90/120 Hz，因此滤波系数必须由实际 `deltaTime` 计算，以保持跨刷新率的一致响应。

## 4. 方案选择

采用“新增纯逻辑单模式 6DoF 控制器，Unity 层只负责输入与输出适配”的方案。

不采用仅修改 Inspector/启动参数的最小方案，因为旧分支仍可能覆盖标准路径；也不完全重写整个遥操作控制器，以控制当前阶段的回归范围。

旧三模式类和可选输入分支暂时保留为兼容代码，但 Quest 默认运行配置不再进入它们。待本方案通过分级验证后，再单独决定是否删除遗留代码。

## 5. 架构与职责

### 5.1 `Ur5Continuous6DofConfig`

新增版本化配置，字段名称必须包含单位，Inspector 字段提供 Tooltip，并在容易误解的数学位置添加必要中文注释。

配置至少包含：

- 配置版本；
- 平移近端增益和远端增益；
- 平移增益过渡距离（米）；
- 旋转近端增益和远端增益；
- 旋转增益过渡角（度）；
- 位置和旋转滤波时间常数（秒）；
- 单次离合最大 TCP 位移（米）；
- 单次离合最大 TCP 旋转（度）；
- 最大线速度（米每秒）；
- 最大角速度（度每秒）。

所有配置进入统一校验函数。NaN、Infinity、负时间常数、倒置的近远端增益或非法限制均不得进入控制计算。

### 5.2 `Ur5Continuous6DofClutchController`

该类位于 `Assets/Scripts/UR5/ControlLogic/`，不读取 Unity XR 设备、不寻找场景对象，也不直接写 `Transform`。其职责是：

- 管理 `Idle / Clutched / Paused / Fault`；
- 捕获右手柄和实际 TCP 基准；
- 计算连续非线性的相对平移与相对四元数；
- 生成逻辑目标；
- 对无效输入执行默认停止；
- 暴露诊断值和明确的 Fault 原因。

### 5.3 Unity 适配层

`Ur5CartesianVelocityTeleopController` 的标准运行链路只负责：

1. 读取右手位置、右手旋转和右手 Grip；
2. 将 XR 位姿通过现有 `xrOrigin` 变换到 Unity 世界坐标；
3. 读取实际 TCP 位姿和安全状态；
4. 调用纯逻辑 6DoF 控制器；
5. 应用工作空间与硬安全限幅；
6. 写入 `TcpTarget` 并记录诊断。

`Ur5ControlBootstrap.ApplyDefaultQuestTeleopProfile` 必须显式启用新单模式控制器，并关闭标准链路中的：

- A/B 三模式请求；
- 左摇杆旋转；
- 左手 Y 姿态旋转；
- 自动竖直吸附；
- Grip 期间的姿态轴锁；
- 重复的输入滤波、目标死区和第二级目标平滑。

## 6. 状态机

### 6.1 Idle

- 进入条件：Grip 未按下，或 Fault 后操作者已经松开 Grip。
- 行为：不生成新的运动目标，不继续滤波尾部追赶。

### 6.2 Clutched

- 进入条件：Grip 按下沿出现，输入位姿、实际 TCP 和安全状态均有效。
- 进入动作：同时捕获右手柄基准和实际 TCP 基准；滤波状态初始化为实际 TCP。
- 行为：从固定基准计算每一帧目标。

### 6.3 Paused

- 进入条件：显式暂停，或左手 X 安全姿态复位等其他受控写入源取得所有权。
- 行为：清除当前离合基准，不接受旧离合输入。
- 恢复：只有其他写入源释放且 Grip 重新按下，才重新捕获基准。

### 6.4 Fault

- 进入条件：XR 跟踪无效、位置或四元数非有限、实际 TCP 无效或安全层拒绝。
- 行为：立即停止生成运动目标，清除离合基准，并锁存 Fault。
- 恢复：必须先松开 Grip，再在输入和安全状态有效时重新按下。

## 7. 6DoF 相对映射

### 7.1 平移

设右手柄世界坐标位置为 `p_hand`，Grip 基准为 `p_hand_anchor`，实际 TCP 基准为 `p_tcp_anchor`：

```text
delta_hand = p_hand - p_hand_anchor
distance = |delta_hand|
blend = SmoothStep(0, translation_transition_m, distance)
gain = Lerp(translation_near_gain, translation_far_gain, blend)
delta_tcp = delta_hand * gain
target_position = p_tcp_anchor + ClampMagnitude(delta_tcp, max_clutch_translation_m)
```

不使用硬位置死区。Quest 的微小追踪噪声通过较低近端增益和唯一的一层时间滤波衰减，避免死区带来的粘滞和起步突变。

初始参数：

- 近端增益：0.15；
- 远端增益：0.80；
- 过渡距离：0.040 m。

### 7.2 旋转

首先归一化当前手柄和基准四元数，并用四元数点积统一符号，保证最短路径：

```text
delta_rotation = q_hand * inverse(q_hand_anchor)
```

将相对旋转转换为最短角度的 angle-axis 表达，仅用于计算连续增益和限幅，不使用欧拉角：

```text
angle = shortest_signed_angle(delta_rotation)
blend = SmoothStep(0, rotation_transition_deg, |angle|)
gain = Lerp(rotation_near_gain, rotation_far_gain, blend)
scaled_delta = AngleAxis(angle * gain, axis)
target_rotation = scaled_delta * q_tcp_anchor
```

目标四元数再次归一化。该左乘顺序与参考项目一致，使控制器在世界坐标中的相对转动施加到离合时的工具姿态。

初始参数：

- 近端增益：0.25；
- 远端增益：0.80；
- 过渡角：20°。

Grip 控制期间完整开放 yaw/pitch/roll，不执行自动竖直吸附和隐式姿态轴锁。

### 7.3 坐标约束

手柄局部位姿必须先通过现有 `xrOrigin` 转换为世界位姿。TCP 目标保持为 Unity 世界位姿，由现有机器人基座和 IK 链路继续处理。

不得新增只适用于当前场景的硬编码轴交换、符号翻转或固定欧拉角补偿。坐标行为继续由第 9.2 阶段的单轴测试约束。

## 8. 单级平滑与硬限制

逻辑目标只执行一层、与刷新率无关的时间滤波：

```text
alpha = 1 - exp(-delta_time / time_constant)
filtered_position = Lerp(previous_position, requested_position, alpha)
filtered_rotation = Slerp(previous_rotation, requested_rotation, alpha)
```

初始位置和旋转时间常数均为 0.055 s。时间常数可分别配置，但首轮验证使用相同数值，减少不必要的调参自由度。

工作空间和单次离合增量在生成目标时约束；最大线速度和最大角速度作为滤波后的硬安全限幅。硬限幅只在越界时介入，不作为常规第二级平滑器。

以下旧处理不得叠加到标准链路：

- 控制器位置的第二级低通；
- 目标位置死区；
- 第二次 TCP 指数平滑；
- 加速度限制形成的松手后追赶轨迹；
- 反馈滞后的实际 TCP 去持续重写离合目标。

Grip 松开时保留最后已经输出的 TCP 目标，但停止一切后续插值和追赶。

## 9. 输入所有权

- 右手 Grip 是标准 6DoF 遥操作的唯一离合输入；
- 右手扳机继续只控制夹爪；
- A/B 不改变运动增益或约束；
- 左摇杆和左手 Y 不生成标准旋转目标；
- 左手 X 可作为显式安全姿态复位，但仅在右手 Grip 未按下时有效；
- 若左手 X 复位取得写入权，单模式控制器进入 Paused，并要求下一次 Grip 按下重新离合。

## 10. 安全与输出边界

- 本次修改不启用真实机器人输出；
- `enableRealRobotOutput` 必须保持关闭；
- 不改变现有真实机器人、网络和 URScript 安全开关；
- 工作空间、速度、角速度和单步增量限制继续位于所有运动目标必经路径；
- Unity 调试目标不能作为真实机器人状态；
- 无效输入和安全拒绝默认停止，不能保持最后速度命令继续运动。

## 11. 诊断

诊断至少暴露或记录：

- 原始右手位置和四元数；
- Grip 状态；
- 控制状态和 Fault 原因；
- 相对手柄距离与相对旋转角；
- 当前连续平移和旋转增益；
- 逻辑目标位置与旋转；
- 滤波后目标位置与旋转；
- 工作空间、线速度或角速度限幅是否介入。

诊断字段必须能区分“没有收到旋转输入”“旋转增益后接近零”“安全层拒绝”和“目标已发送但 IK 未跟随”。

## 12. 测试设计

先用测试驱动实现纯逻辑，再接入 Unity 主控制器。

### 12.1 单元测试

1. Grip 按下基准点不移动 TCP。
2. Grip 松开后不再生成目标。
3. 重复离合使用新的实际 TCP 基准且无目标突跳。
4. X/Y/Z 三个单轴平移只产生预期轴变化。
5. yaw/pitch/roll 三个单轴旋转只产生预期旋转。
6. 组合旋转使用四元数复合，跨越 180° 时走最短路径。
7. 平移和旋转增益曲线单调，并在过渡端点连续。
8. 1 mm 输入按 0.15 近端增益映射为约 0.15 mm。
9. 1° 输入按 0.25 近端增益映射为约 0.25°。
10. 最大离合位移和旋转角正确限幅。
11. NaN、Infinity、零模四元数和安全拒绝进入 Fault。
12. Fault 在 Grip 未松开前不会自动恢复。
13. 相同输入轨迹在 72/90/120 Hz 下经过相同时长后，位置差不超过 0.5 mm、旋转差不超过 0.1°。

### 12.2 Unity 集成测试

1. Quest 默认配置的输入节点为右手位置、右手旋转和右手 Grip。
2. A/B、左摇杆和左手 Y 不改变标准 TCP 运动目标。
3. 自动竖直吸附在标准 Grip 链路关闭。
4. 左手 X 与右手 Grip 不会同时写入目标。
5. Grip 松开同帧之后不再记录遥操作目标写入。
6. 工作空间和速度安全限制仍然生效。
7. 现有 URDF、IK、夹爪和场景测试不回归。
